# 流程与状态

## 建议目录

在用户指定的项目目录下保存运行产物，不把账号数据写进 Skill 本体。

```text
project/
  account.md
  direction-decision.md
  benchmarks/
  topic-queue.md
  test-plan.md
  assets/
  posts/
    YYYY-MM-DD-slug/
      brief.md
      title.txt
      body.txt
      images/
      preview.html
      internal-record.md
      metrics.md
```

## 状态与证据

前期按“方向待选 → 方向已定 → 样本已建 → 选题待制作”推进。单篇用 [post-record.md](../assets/post-record.md) 分开记录三件事：

| 字段 | 可用状态或动作 | 推进依据 |
| --- | --- | --- |
| 制作状态 | 待补素材 / 待审阅 / 成品已确认 | 最终文件齐全进入待审阅，使用者确认具体成品后进入成品已确认 |
| 已授权动作 | 仅本地制作 / 保存草稿 / 发表这份具体成品 | 使用者对内容范围、目标账号和动作的授权 |
| 后台状态 | 未保存 / 保存结果待核验 / 已存草稿 / 审核中 / 已发表 | 平台实际显示和内容回读 |

这些字段相互独立：待审阅的完整稿可以按授权存入草稿箱；成品已确认不代表已经上传，已存草稿不代表允许发表。只存草稿的任务在保存核验完成后结束。

状态只能由可见证据推进：

- 用户说出选择，才能进入“方向已定”。
- 最终图片与正文齐全，才能进入“待审阅”。
- 用户确认具体成品，才能进入“成品已确认”。
- 草稿列表出现对应条目，且重新打开能核对标题、正文和图片，才能进入“已存草稿”。
- 平台回读显示已发表，才能进入“已发表”。
- 记录真实时间和指标，才能进入“已观察”。

## 每阶段输出

| 阶段 | 必要输出 |
| --- | --- |
| 方向选择 | 三个候选或用户已有方向、选择依据、停止条件 |
| 对标研究 | 样本表、已打开范围、不可访问项、可借结构 |
| 首轮计划 | 按用户要求确定数量，未指定时建议 7—14 个题目；所需素材、依据、测试变量 |
| 单篇制作 | 制作卡、标题、正文、图片顺序、内部来源、预览、缺项 |
| 保存草稿 | 目标账号、逐篇内容标识、保存回读时间、重新打开的内容核对结果 |
| 发布 | 目标账号、用户批准记录、平台状态、时间、内容标识 |
| 复盘 | 观察窗口、真实指标、判断边界、下一项改动 |

## 自动化边界

方向候选、网页研究、样本拆解、选题、素材候选、文案、预览、检查和复盘可以由智能体执行。保存草稿或发表按使用者已授权的范围执行；最终方向、对外内容审阅、实名扫码、协议接受由本人处理。平台工具不可用时，交付完整的发布包和清楚的手动步骤，不宣称已存草稿或已发表。明确的网站访问策略拒绝不能通过更换工具绕过，恢复方法见 [publishing-and-review.md](publishing-and-review.md)。
