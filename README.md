# WeChat Sticker Operator

一个用于运营微信公众号贴图号的 Codex Skill。

它把“选方向、找对标、找图片、逐页写内容、保存草稿、发布准备、记录数据和复盘”整理成一套可以重复执行、可以检查结果的流程。

## 它能做什么

- 根据使用者的素材、时间和目标，给出三个具体方向候选。
- 由使用者本人选择方向后，寻找同类型账号和近期内容作为对标。
- 拆解对标的目标人群、使用场景、首图、标题、正文交付和互动方式。
- 生成首轮选题，并列出每个选题需要的图片与事实依据。
- 寻找和核验可使用的真实照片，保存作者、原始页面和使用条件。
- 用制作卡安排每页新增的信息，检查标题承诺、画面细节和正文是否一致。
- 制作标题、正文、图片顺序和手机预览，检查相邻选题是否重复。
- 按授权保存到公众号草稿箱，回到列表并重新打开，逐篇核对内容是否保留。
- 在具体成品获得确认后，协助进行公众号发布。
- 记录真实发表状态、运营数据和收益口径，并据此复盘。

## 核心流程

```text
填写启动问卷
    ↓
生成三个方向候选
    ↓
使用者选择一个方向
    ↓
寻找并拆解同类型对标
    ↓
建立 7—14 条首轮选题
    ↓
寻找素材并制作图文
    ↓
手机预览与人工审阅
    ↓
按授权保存草稿，或发表已确认成品
    ↓
记录真实数据并复盘
```

已有明确方向时，直接进入相应阶段。方向未确认时，Skill 不生成待发布稿。图片、事实或使用条件没有核验完成时，内容保留为“待补材料”。只要求保存草稿的任务，在保存并回读完成后结束，不进入发表和数据复盘。

## 安装

把整个仓库复制到 Codex 的 Skills 目录：

```text
~/.codex/skills/wechat-sticker-operator
```

也可以克隆仓库：

```bash
git clone https://github.com/kimxiao520-source/wechat-sticker-operator.git
```

然后将仓库目录放入当前智能体能够读取的 Skills 路径。

## 使用

在 Codex 中调用：

```text
$wechat-sticker-operator
```

第一次可以这样说：

```text
使用 $wechat-sticker-operator 帮我做一个微信公众号贴图号。
先根据我的情况给出三个方向，我选定以后再找对标和做第一轮内容。
```

已有方向时可以直接说：

```text
使用 $wechat-sticker-operator。
我的方向是面向上班族的家常饭实拍，请先找同类型对标并准备 10 个测试选题。
```

已有文章时也可以从中间阶段开始：

```text
使用 $wechat-sticker-operator 检查这篇文章的标题、首图、正文和素材来源，整理成待审阅发布稿。
```

只存草稿、自己发表时可以说：

```text
使用 $wechat-sticker-operator，把这 10 篇完整稿存进指定账号的草稿箱，我自己发。
逐篇回到草稿列表并重新打开核对，给我保存结果和未完成项。
```

本地文件准备好、上传按钮点击成功和后台草稿已保留是不同结果。遇到断线，先查现有草稿再重试；工具明确拒绝访问网站时，保留具体错误并停止该站点操作，不用另一种工具绕过。

## 重要原则

### 使用者先选方向

Skill 可以研究和整理方向候选，但最终方向由使用者选择。已经有明确方向时，不强制重新三选一。

### 对标不等于照搬

对标用于学习人群、场景、首图、标题和信息结构。正式内容需要重新核验事实、寻找可使用素材并独立写作。

### 图片来源必须可核验

对标截图、搜索缩略图和二次转载页不能直接成为发布素材。采用的图片需要记录原始页面、作者、使用条件和实际修改。

### 发布需要具体授权

Skill 会先交付可以审阅的完整成品。只有使用者确认具体标题、正文、图片和目标账号后，才进入发表操作。实名、扫码和协议确认由本人完成。

### 只用真实结果复盘

制作状态、已授权动作和后台状态分开记录。草稿保存需要列表条目和重新打开的内容核对；发表需要平台实际显示已发表。阅读量不等于收入，收益需要区分预估、已结算和已到账，并同时记录成本。

## 方法参考

制作卡和测试计划参考了宋宋的 [《不会写长文，也能做公众号》](https://x.com/songsong/status/2090766180349030527) 正文：从一个具体需求出发，让每页增加有用信息，让标题、首图和交付一致，再从真实反馈中选择下一轮调整。原文附图和部分表格未逐项核验，不作为模板中的事实依据；作者的频率、阅读阈值、流量和收益主张不作为本 Skill 的保证或平台规律。

## 能力边界

这个 Skill 提供运营流程和任务规范。它会使用运行环境中已有的网页搜索、浏览器或平台工具；如果环境没有这些能力，就交付研究清单或发布包，不假装已经检索或发表。

它不承诺流量或收益，也不通过虚假点击、编造经历、搬运原图原文等方式制造结果。
